Inside the Database: Build Roadmap

One database, built bottom-up in layers. Each layer is a chapter, a tagged commit and a CV bullet, but only once it has tests and numbers behind it. C++ is the default; Java works for every layer.

Short on time? Phases 1 to 3 are the core for your Amazon application: data structures, a storage layer, and a KV engine with a B+ tree and an LSM tree. A tested LSM store plus B+ tree beats seven half-finished layers. Add the rest as time allows.

The phases

Added beyond the original plan

Skip list and extendible hashing

The skip list becomes your memtable. Extendible hashing gives you a disk-friendly hash index to compare with the B+ tree.

Slotted pages and MVCC

Slotted pages are how real engines store variable-length rows. MVCC with snapshot isolation is how most modern databases avoid read locks.

Columnar mini-engine

Dictionary and run-length encoding with vectorised scans. One extra engine type shows range beyond the row store.

Real DynamoDB exercise

A small app using the AWS SDK. Your own KV store shows transferable knowledge, but it isn’t the same as having used the service.

Crash-consistency harness

Kill the process at every write boundary, restart, and verify acknowledged writes survived. This plays to your testing background.

Raft replication (last)

Strong, but 6 to 10 weeks. None of Amazon’s five listed areas need it, so treat it as a stretch goal.

Definition of done, per component

Tests

Unit, edge-case and failure tests. Property tests for invariants. Sanitizers (ASan, UBSan, TSan) clean in CI.

Numbers

A benchmark with throughput and p50/p95/p99 latency against a baseline such as RocksDB, SQLite or std::map.

Words

A one-page design doc: problem, approach, trade-offs, what failed. This becomes the book chapter.

Study CMU 15-445 and MIT 6.5840 for concepts, but write your own code and explanations. Check course rules before publishing anything assignment-derived. Don’t claim crash safety or thread safety on your CV until the tests prove it.
