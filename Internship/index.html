The phases

Java-specific things to get right

Durability

FileChannel.force(true) is your fsync. Also sync the directory after creating or renaming a file, or the rename can be lost in a crash.

Benchmarking

The JIT makes naive timings meaningless. Use JMH, and record GC logs so you can explain p99 spikes.

Memory

Large heaps of small objects stress the GC. Store pages and blocks in ByteBuffers or byte arrays, and consider off-heap buffers for the buffer pool.

Concurrency testing

Java has no ThreadSanitizer. Use jcstress for memory-model tests, plus randomised multi-thread stress tests that compare against a simple model.

Read real Java code

Cassandra (memtable, SSTable, compaction), H2 or HSQLDB (a full SQL engine) and Apache Calcite (a query planner and optimiser) are all open source.

Crash tests

Run the database in a child process, kill it with SIGKILL at random points, restart, and verify every acknowledged write survived.

Definition of done, per component

Tests

JUnit 5 unit and edge-case tests, jqwik property tests for invariants, and crash tests, all running in GitHub Actions.

Numbers

A JMH benchmark with throughput and p50/p95/p99 latency against a baseline such as RocksDB through its Java binding, H2, or TreeMap.

Words

A one-page design doc: problem, approach, trade-offs, what failed. This becomes the book chapter.
