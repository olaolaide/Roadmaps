Phase 01 — HTTP & Networking

Core topics
  • HTTP methods: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS
  • Status codes: 2xx success, 3xx redirect, 4xx client error, 5xx server error
  • Critical headers: Content-Type, Accept, Authorization, Cache-Control, ETag, If-None-Match
  • CORS — preflight requests, Access-Control-Allow-* headers, why it matters for API testing
  • Cookies: Set-Cookie, HttpOnly, Secure, SameSite, session vs persistent
  • SSL/TLS handshake, certificate validation, how to test with self-signed certs
  • Request body formats: JSON, XML, form-urlencoded, multipart/form-data
Practice tasks
  • Use browser DevTools Network tab — inspect every header on 5 real sites
  • Send each HTTP method manually in Postman to a public API (JSONPlaceholder)
  • Trigger and document a CORS error — understand the preflight flow
  • Test with an expired SSL cert using a local proxy tool
  • Write 20 test scenarios covering header validation (missing, malformed, unexpected values)
  • Build an HTTP reference cheat sheet — methods, codes, headers, and their test impact

Phase 02 — REST API & CRUD

REST architecture
  • 6 REST constraints: stateless, uniform interface, layered system, cacheable, client-server, code on demand
  • Resource naming conventions — nouns not verbs, plural collections
  • Idempotency: GET, PUT, DELETE are idempotent — POST is not
  • Pagination patterns: offset/limit, cursor-based, page/per_page — what to assert on each
  • Filtering and sorting: query param conventions, test for injection via filters
  • Content negotiation: Accept header, versioning via URL vs header
Full CRUD test checklist
  • CREATE — valid body, required field missing, wrong data type, duplicate resource (409)
  • READ — valid ID, non-existent ID (404), unauthorised (401/403), empty collection (200 [])
  • UPDATE (PUT) — full update, partial fields, immutable fields, version conflict (409)
  • UPDATE (PATCH) — partial update, no-op patch, malformed patch body
  • DELETE — valid delete, already deleted (404 or 204), cascade behaviour
  • LIST — pagination boundaries, filter with no results, sort ordering, response envelope validation

Phase 04 — OpenAPI & Swagger

Spec mastery & contract validation
  • OpenAPI 3.x structure: info, servers, paths, components, schemas, securitySchemes
  • Schema types: string, integer, array, $ref, oneOf/anyOf/allOf
  • Contract testing: assert response body matches OpenAPI schema — use Spectral or Pact
  • Required vs optional fields: test API behaviour when optional fields are absent
  • Enum validation: assert only documented enum values are returned
  • Postman collection generation directly from OpenAPI spec import
OpenAPI → C# pattern
  • Install OpenAPI Generator CLI or NSwag
  • Generate C# DTOs: all request/response models as typed classes
  • Generate RestSharp methods: one method per endpoint with typed parameters
  • Validate generated models against live API responses as a contract test
  • BDD template generation: for each endpoint in the spec, scaffold a Gherkin scenario (Given the API is running / When I POST to /users / Then the response is 201)
  • Keep generated code in a Generated/ folder — regenerate on spec change, do not hand-edit

Phase 05 — Security & Auth Testing

Auth concepts to master
  • JWT anatomy: header.payload.signature — decode and inspect on jwt.io
  • JWT validation tests: expired token, tampered signature, missing claims, wrong audience
  • Bearer token pattern: Authorization: Bearer {token} — test missing, malformed, revoked
  • OAuth 2.0 flows: Authorization Code (web apps), PKCE (SPAs/mobile), Client Credentials (M2M)
  • OpenID Connect: ID token vs access token, userinfo endpoint, scope: openid profile email
  • RBAC: test each role against every endpoint — assert correct 403 on unauthorised actions
Security test case checklist
  • No token → 401 Unauthorized
  • Expired token → 401 with meaningful error body
  • Token from different environment (prod token on staging) → 401
  • Tampered payload (Base64 edit) → 401 signature invalid
  • Privilege escalation: user A accesses user B's resource → 403
  • Mass assignment: send admin:true in request body → verify it is ignored
  • SQL injection via query params → no 500, no data leak
  • Rate limiting: exceed threshold → 429 Too Many Requests
  • Sensitive data in response: no passwords, no raw PII beyond scope
  • CORS: cross-origin request without credentials → verify allowed origins

Phase 06 — C# RestSharp Enterprise Framework

Framework architecture
  • APIFramework/ structure: Clients/, Models/, Services/, Config/, Helpers/, Tests/, Reports/, TestData/
  • BaseApiClient: wraps RestClient, adds default headers, base URL, timeout, serialiser config
  • Constructor injection: IConfigurationHelper → BaseApiClient → feature client classes (UserClient, OrderClient)
  • TokenManager: handles login, caches JWT, refreshes on expiry — injected into BaseApiClient
  • Typed response wrapper: ApiResponse<T> with StatusCode, Data, ErrorMessage — no raw RestResponse in tests
  • Shared request builder: BuildRequest() attaches auth header, content-type, correlation ID from config
Code pattern
// BaseApiClient.cs public class BaseApiClient { private readonly RestClient _client; private readonly ITokenManager _tokens; public BaseApiClient( IConfigHelper cfg, ITokenManager tokens) { _client = new RestClient(cfg.BaseUrl); _tokens = tokens; } protected async Task<ApiResponse<T>> SendAsync<T>(RestRequest req) { req.AddHeader("Authorization", $"Bearer {await _tokens.GetToken()}"); var r = await _client.ExecuteAsync<T>(req); return new ApiResponse<T>(r); } }

Phase 07 — GraphQL Testing

GraphQL test areas
  • Query testing: request only needed fields, assert no extra fields leak, test nested objects
  • Mutation testing: create/update/delete via mutation — assert response + side-effect via query
  • Partial failure: GraphQL returns 200 even on errors — must check errors[] array, not just status code
  • Variables: test with null, wrong type, missing required variable
  • Aliases and fragments: ensure test coverage handles aliased field names in response parsing
  • Auth testing: unauthenticated query → errors[] contains auth error, not data leak
Introspection & security risks
  • Introspection query exposes full schema — must be disabled in production
  • Test: send __schema query → production should return 400 or empty; staging is acceptable
  • Field-level auth: user without admin role queries adminOnlyField → expect null or error, not data
  • Deeply nested queries (DoS risk): send query with 10 levels of nesting → server should limit depth
  • Batch query attacks: send array of operations — assert rate limiting applies to batch requests
  • Use GraphQL Playground or Altair for exploratory testing before automating

Phase 08 — BDD with Reqnroll / SpecFlow

Core BDD concepts
  • Gherkin: Feature, Background, Scenario, Scenario Outline, Given/When/Then/And/But
  • Step definitions: binding a Gherkin step to a C# method via [Given], [When], [Then] attributes
  • ScenarioContext: share state between steps — store response, tokens, created resource IDs
  • Hooks: [BeforeScenario] for setup (get token), [AfterScenario] for teardown (delete created resource)
  • [BeforeFeature] / [AfterFeature] for suite-level setup
  • Tags: @smoke @regression @auth — run subsets via dotnet test --filter Category=smoke
Gherkin scenario — create user
Feature: User Management Background: Given I am authenticated as an admin @smoke @regression Scenario: Create a new user successfully Given I have a valid user payload | field | value | | firstName | Abimbola | | lastName | Olaide | | email | a.olaide@test.com | | role | tester | When I POST to "/api/users" Then the response status is 201 And the response contains a user id And the email is "a.olaide@test.com" Scenario: Reject duplicate email Given a user with email "a.olaide@test.com" exists When I POST to "/api/users" with the same email Then the response status is 409 And the error message is "Email already registered"
Step definitions — C# pattern
// CreateUserSteps.cs [Binding] public class CreateUserSteps { private readonly ScenarioContext _ctx; private readonly UserClient _users; public CreateUserSteps( ScenarioContext ctx, UserClient users) { _ctx = ctx; _users = users; } [When(@"I POST to ""/api/users""")] public async Task PostUser() { var payload = _ctx.Get<UserDto>("payload"); var resp = await _users.CreateAsync(payload); _ctx.Set(resp, "response"); } [Then(@"the response status is (.*)")] public void AssertStatus(int expected) { var resp = _ctx.Get<ApiResponse<UserDto>> ("response"); resp.StatusCode.Should().Be(expected); } }
  • Reqnroll handles DI via BoDi container — register UserClient in [BeforeScenario] hook
  • ExtentReports or LivingDoc for BDD HTML output
  • GitHub Actions: dotnet test → upload .html report as artifact on every push
