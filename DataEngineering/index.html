The Path

Eleven phases, in order

Each phase compounds the one before it. Tap a phase to expand it.

01
Foundation

Data
Everything above this layer inherits its weaknesses — don't rush it.
In plain EnglishData is just information — names, numbers, dates, clicks. Python is the language you use to tell a computer "go get this data and do something with it." SQL is how you ask a database questions, like "show me every customer who bought something last week." Before you can build anything smart, you need to be able to fetch, clean, and store information reliably. That's this whole phase.

Python

  • Fundamentals — variables, loops, if/else (the basic building blocks)
  • OOP, modules/packages — organising bigger programs
  • Typing, error handling, testing — writing code that doesn't quietly break
  • Virtual environments, APIs — talking to other systems over the internet
  • pandas, NumPy — the toolkits for wrangling spreadsheets and numbers in code

SQL

  • SELECT, JOINs — pulling and combining data from tables
  • GROUP BY, subqueries, CTEs — summarising and breaking big questions into steps
  • Window functions, views, indexes — advanced tricks + making queries fast
  • Query optimisation, EXPLAIN — figuring out why a query is slow and fixing it
  • Transactions, ACID, isolation levels — making sure data never gets corrupted

Database

  • PostgreSQL first — the industry-standard relational database to learn on
  • OLTP vs OLAP — systems built for daily transactions vs. big analysis
  • Dimensional modelling, star schema, slowly changing dimensions
  • Partitioning, indexing — splitting and organising data so it stays fast at scale

Data Visualization

  • Tableau, Power BI — the dashboard tools Fortune 500 companies use every day so non-technical managers can see the data
  • matplotlib, seaborn, Plotly (Python) — building charts straight from your own code
  • Chart choice — knowing when a bar chart, line chart, or heatmap actually tells the story vs. just looking pretty
  • Dashboard design — one clear message per screen, not twenty numbers crammed in
02
Foundation

Data Engineering
This is where you stop being a scripter and become a Data Engineer.
In plain EnglishImagine a factory. Raw materials (messy data from apps, sales systems, sensors) come in one end, and clean, useful data comes out the other. ETL/ELT is that factory line: Extract it, Transform it (clean it up), Load it somewhere useful. Spark is what you use when there's too much data for one computer, so the work gets split across hundreds of machines at once. Kafka handles data that never stops arriving — like a live feed of every purchase happening on Amazon right now.

ETL / ELT

  • Python + SQL → dbt (transform) → Airflow (schedule it all)
  • Ingestion, transformation, orchestration — get it, clean it, run it on time
  • Scheduling, retries, dependency management — what runs when, and what to do if it fails
  • Data quality, lineage — catching bad data, and tracing where any number came from

Big Data — Spark

  • RDDs, DataFrames, Spark SQL — the building blocks for huge datasets
  • Partitioning, shuffles, joins, caching — how work gets split across machines efficiently
  • Catalyst optimiser, cluster architecture — how Spark quietly makes your code faster

Streaming — Kafka

  • Producers, consumers, topics, partitions — who sends data, who reads it, and how it's organised
  • Offsets, consumer groups, replication — not losing data even if a machine crashes
  • Kafka Streams, event-driven architecture — reacting to things the instant they happen
03
Foundation

Cloud — AWS
One cloud, deeply, not three shallowly — go deep on AWS before touching Azure or GCP.
In plain English"The cloud" just means renting computers and storage from a giant company (Amazon, Microsoft, Google) instead of buying your own servers. AWS is Amazon's version, and it's the biggest one, so most Fortune 500 companies already use it. S3 is basically an unlimited hard drive on the internet. Lambda lets your code run for a few seconds without you needing to keep a computer switched on 24/7. Learning AWS well means you can build real systems without ever owning a physical machine.

Storage & Compute

  • S3 — a giant internet hard drive for files
  • EC2 — a rentable computer you can switch on and off
  • EMR — a cluster of computers running Spark for you

Data & Streaming

  • Glue — cleans and moves data automatically (ETL)
  • Redshift — a warehouse built for big analytics queries
  • Athena — lets you query files sitting in S3 with plain SQL
  • Kinesis — AWS's version of a live, never-stopping data feed
  • Lambda — code that runs by itself, only when needed

Platform

  • IAM — decides who's allowed to touch what
  • CloudWatch — the dashboard that watches if anything breaks
  • CloudFormation → Terraform — writing your infrastructure as code instead of clicking buttons
04
Platform

Lakehouse — Databricks
Used by roughly 70% of Fortune 500 companies — one of the highest-value technologies in the whole roadmap.
In plain EnglishOld-school companies had two separate systems: a "data lake" (cheap storage for messy raw data) and a "data warehouse" (an organised, query-friendly place for reports). A lakehouse is a modern hybrid that gives you both at once — cheap storage AND reliable, organised tables. Databricks is the company that built the most popular version of this. "Bronze / Silver / Gold" is just a fancy way of saying: raw data → cleaned data → ready-for-business data, like ore → metal → a finished part.

Databricks

  • Spark — the processing engine underneath it all
  • Delta Lake — the storage format that adds reliability to raw files
  • Unity Catalog — one place that tracks who can see and use what data
  • MLflow, Databricks SQL — tracking ML experiments and running SQL reports

Lakehouse Architecture

  • Bronze / Silver / Gold layering — raw → cleaned → business-ready
  • Schema evolution — adapting when the shape of your data changes over time
  • Time travel — being able to "rewind" a table to see what it looked like yesterday
  • ACID transactions, data governance — reliability and control over who touches what
05
Platform

Data Architecture
Stop learning tools in isolation — learn to design systems. This is the pivot toward Senior / Platform / Architect track.
In plain EnglishSo far you've learned individual tools. This phase is about learning how senior engineers decide which tools to combine, and why — like knowing not just how to use a hammer and a saw, but how to actually design a house. Graph databases fit here because some data isn't naturally a table — it's a web of connections: "this person knows that person, who bought this product, which is similar to that product." Fortune 500 companies use graph databases for exactly that kind of connected data — fraud rings, recommendation engines, supply chains, org charts.

Architecture Patterns

  • Data warehouse, data lake, lakehouse — where the data physically lives
  • Data mesh — treating each team's data like its own product instead of one giant shared pile
  • Medallion, Lambda, Kappa architectures — named patterns for organising raw-to-ready data flows

Graph Databases

  • Neo4j — the most widely used graph database, and the one to learn first
  • Cypher — the query language for asking "how are these things connected?"
  • Amazon Neptune — AWS's managed graph database, useful once you know Neo4j
  • Graph modelling — nodes (things) and edges (relationships), instead of rows and columns
  • Real Fortune 500 uses: fraud detection, recommendation engines, knowledge graphs, supply-chain mapping

Distributed Systems

  • Partitioning, replication — splitting and copying data across machines safely
  • Consistency, availability, fault tolerance, CAP theorem — the trade-offs every large system has to make

Governance

  • Cataloguing, lineage — knowing what data exists and where it came from
  • RBAC — controlling access by someone's role, not one person at a time
  • Data quality, PII, encryption, access control — keeping data accurate, private, and safe
06
Intelligence

Machine Learning
Notice the order: ML is built on top of the engineering foundation, not started from it.
In plain EnglishMachine learning is teaching a computer to spot patterns in data instead of you writing exact rules by hand. Show it thousands of past examples ("this customer left, this one didn't") and it learns to predict new ones. You need a bit of maths to understand why it works, but scikit-learn does most of the heavy lifting — you're mainly choosing the right approach and checking the computer's guesses are actually good.

Mathematics

  • Probability, statistics
  • Linear algebra, calculus basics
  • Optimisation

scikit-learn

  • Regression, classification, clustering
  • PCA, feature engineering
  • Cross-validation, hyperparameter tuning
  • Model evaluation

Gradient Boosting

  • XGBoost
07
Intelligence

ML Engineering
This is where the profile becomes materially harder to replace.
In plain EnglishBuilding a smart model on your laptop is easy. Keeping it running correctly for millions of real users, every day, without breaking — that's the hard part, and that's ML Engineering. MLflow is like a lab notebook that remembers every experiment you tried. Docker packs your code into a box that runs the same way on any computer. FastAPI lets other programs ask your model for a prediction over the internet.

MLflow

  • Training → tracking → registry
  • Deployment → monitoring

MLOps

  • Model versioning, experiment tracking
  • Feature stores, model registry, serving
  • Monitoring, drift, reproducibility, CI/CD

Deployment

  • FastAPI, Docker
  • Kubernetes — enough to understand production, not administer clusters
08
Intelligence

Deep Learning
The goal is to understand and deploy modern ML systems — not to become a research scientist.
In plain EnglishDeep learning is machine learning's more powerful cousin — instead of one simple pattern-spotting trick, it stacks thousands of tiny connected "neurons" in layers, loosely inspired by how brains work. This is what lets computers recognise faces in photos, understand speech, and — most importantly for this roadmap — understand and generate human language. Everything in the next phase (LLMs) is built using this.

PyTorch

  • Tensors, autograd
  • Neural networks, training loops

Architectures

  • CNNs, RNNs
  • Attention, Transformers
09
Frontier

AI Engineering
The final major layer before the agentic frontier.
In plain EnglishAn LLM (like the model behind ChatGPT or Claude) is a deep learning model trained on huge amounts of text, so it's good at predicting "what word comes next." RAG means: instead of expecting the LLM to already know everything, you first fetch the exact relevant facts from your own company's data, hand them to the LLM, and say "answer using this." It's like giving someone an open-book exam instead of expecting them to memorise the textbook.

LLM Fundamentals

  • Transformers — the architecture almost every modern LLM is built on
  • Embeddings — turning words/sentences into numbers a computer can compare
  • Tokenisation — how text gets chopped into pieces the model actually reads
  • Context windows, inference — how much the model can "see" at once, and how it answers
  • Fine-tuning, LoRA / PEFT — teaching an existing model your own specific data cheaply

RAG Pipeline

  • Chunking — cutting documents into bite-sized pieces
  • Embeddings → vector database — turning those pieces into searchable numbers
  • Retrieval → reranking → LLM — finding the best matches, sorting them, then answering

Vector Databases

  • pgvector first, in depth — vector search added right inside PostgreSQL
  • Then Pinecone, Milvus, Weaviate — awareness, not all three mastered
  • GraphRAG — combining your Phase 05 graph database skills with RAG, so the model can follow relationships ("who reports to whom," "which parts depend on which") instead of just matching similar text — a fast-growing 2026 pattern for Fortune 500 knowledge systems
10
Frontier

Agentic AI
LLM → Tools → Memory → Retrieval → Agents → Production. Increasingly what "enterprise AI" means in practice.
In plain EnglishA regular LLM can only talk. An "agent" is an LLM that can also act — it can decide "I need to check the database," actually run that check using a tool, look at the result, and decide what to do next, on its own, in a loop. Think of the difference between a person who can only give you advice over the phone, versus a personal assistant who can actually go do the task for you and report back.

Agent Systems

  • Tool calling, function calling — letting the model actually run code or hit an API
  • Agent workflows — chaining steps: think, act, observe, repeat
  • MCP (Model Context Protocol) — the emerging standard for connecting AI models to real tools and data

Reliability

  • Evaluation — testing whether the agent actually does the right thing, reliably
  • Guardrails — stopping the agent from doing something risky or wrong
  • Observability — being able to see what the agent did and why, after the fact
  • Multi-agent systems — several agents working together on different parts of a task
11
Delivery

Production
This is what separates a portfolio project from something that reads as Fortune 500 engineering.
In plain EnglishA school project just needs to work once, on your laptop, while you're watching it. A production system needs to keep working at 3am, handle way more users than expected, recover on its own if something crashes, and let other engineers safely change it without breaking everything else. This phase is about taking everything from Phases 1–10 and gluing it together into one real, reliable system — the kind of project that actually gets you hired.

Full stack, integrated

  • Git, GitHub — tracking every change to your code and working with a team
  • Docker, Terraform — packaging code reliably, and building infrastructure from code
  • CI/CD — GitHub Actions, Kubernetes — automatically testing, deploying, and scaling your system
  • AWS, Databricks, Airflow, Spark, Kafka — the full data backbone from earlier phases, working together
  • MLflow, FastAPI, PyTorch, LLMs, RAG, monitoring — the ML/AI layer, live and being watched
