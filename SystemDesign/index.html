How this works
  • Build the engine projects in Java and stay with it. The storage and query-engine phases overlap with a Java database build, so reuse that code rather than starting over. The API lab (Phase 11) uses Express and MongoDB, because that is the stack where you practice reading, breaking, and fixing real web code.
  • Chapter names differ between DDIA’s first and second editions, so the reading lists use topic names. Read the topics in the order shown.
  • Each phase: read, then do the timed design exercises, then build the project. The project is where the reading sticks, and it is what you show employers.
45-minute design interview structure
  • High-level design: 5 min requirements and scope · 5 min estimation and API · 10 min data model and diagram · 15 min deep dive on two components · 10 min bottlenecks, failures, trade-offs.
  • Low-level design: 5 min requirements · 10 min entities and relationships · 10 min patterns and class design · 15 min code the core · 5 min extensibility and concurrency.
Every project is done only when it has
  • A README with an architecture diagram and a design-decisions section.
  • Unit tests plus a randomized or fault-injection test (kill processes, drop messages, corrupt files).
  • A benchmark with real numbers (JMH or k6) and a note on what limited throughput.
  • A short write-up of what you would change. Link the repo below.
Bug-hunt method (30 minutes)
  • Reproduce first: run the app and the tests, and trigger the failure before reading code (5 min).
  • Trace the request path: route, middleware, validation, handler, database call, response (5 min).
  • Check the usual suspects: missing await, wrong comparison, unvalidated input, missing authorization, non-atomic update, missing index.
  • Fix properly: write a failing test, make the smallest change that passes, rerun everything.
  • Explain aloud: the root cause, why the fix is right, and where else the same flaw could hide.
