Week 1 — Software testing foundations

Topics to learn
  • SDLC phases: Requirements → Design → Build → Test → Deploy
  • STLC phases: Planning → Analysis → Design → Execution → Closure
  • Test Plan & Test Strategy
  • Agile: sprints, user stories, acceptance criteria, definition of done
  • Verification vs validation · QA vs QC
  • Defect lifecycle: New → Assigned → Open → Fixed → Retest → Closed
  • Severity vs priority
Practice tasks
  • Pick a target site: CRC Website or Demo Web Shop
  • Expand into 20 detailed test cases with steps and expected results
  • Log 10 defect reports — include severity, priority, steps to reproduce, and expected vs actual
  • Produce your first test plan document covering scope, approach, and exit criteria

Week 2 — Functional testing types

Testing types
  • Smoke testing — verify critical path before full regression
  • Sanity testing — narrow focused check after a fix
  • Regression testing — ensure nothing new broke existing features
  • Retesting — explicitly verify the reported defect is fixed
  • Integration testing — component interaction and data flow
  • System testing — full end-to-end system behaviour
  • UAT — end-user acceptance in production-like environment
Practice: login page full coverage
  • Valid login with correct credentials
  • Invalid login with wrong password
  • Empty fields — username and/or password blank
  • Password rules: length minimum, special characters
  • Session timeout behaviour
  • Write at least 30 test cases total across all login scenarios
  • Log 15 bug reports in Excel with full detail

Week 3 — Test design techniques

Techniques to master
  • Equivalence partitioning — group inputs into valid/invalid classes
  • Boundary value analysis — test the edges of valid ranges
  • Decision table testing — map condition combinations to outcomes
  • State transition testing — follow object state changes
  • Exploratory testing — structured ad-hoc discovery
  • Error guessing — use experience to predict likely failures
Practice tasks
  • Apply each technique to a real form or feature on your chosen site
  • Write 30 test cases labelled by technique used
  • Build a requirements traceability matrix (RTM) linking test cases to requirements
  • Identify which technique gives the best defect yield for each feature type

Week 4 — Test management & reporting

Topics to learn
  • Writing a test strategy: objectives, scope, approach, risks
  • Risk-based testing — prioritise by likelihood × impact
  • Test coverage metrics: pass rate, defect density, escape rate
  • Defect density and how to track it over a sprint
  • Sprint test summary report structure
Deliverables
  • Complete test strategy document for your chosen site
  • Consolidated defect log from weeks 1–4
  • 1-page sprint test summary report with pass/fail metrics
  • Lessons learned notes — what you'd do differently

Week 5 — Visual Studio & the .NET toolchain

Visual Studio orientation
  • Installing Visual Studio Community — workloads: .NET desktop + ASP.NET
  • Solution Explorer: solutions, projects, files, and references
  • The editor: IntelliSense, squiggles, quick fixes (lightbulb)
  • Output / Error List / Test Explorer windows
  • Running and stopping a project (F5 vs Ctrl+F5)
  • NuGet Package Manager — install and update packages
  • .NET CLI basics: dotnet new, dotnet build, dotnet test
Debugger deep dive
  • Setting a breakpoint (F9) and running to it (F5)
  • Step over (F10), step into (F11), step out (Shift+F11)
  • Watching variables in the Locals and Watch windows
  • The Call Stack window — trace execution path
  • Conditional breakpoints — break only when a value matches
  • Debug a deliberately broken NUnit test and fix it using the debugger
Why this week exists: Visual Studio can feel overwhelming at first. Spending a week here before writing any automation code means you won't be fighting the IDE at the same time as learning Playwright. The debugger skill you build here pays dividends in every future week.

Week 6 — AI-built framework teaser

Using AI to scaffold
  • Install GitHub Copilot extension in Visual Studio
  • Prompt Copilot to create a new NUnit + Playwright .NET project
  • Ask AI to generate a LoginPage and HomePage using Page Object Model
  • Prompt for a BaseTest class with browser setup and teardown
  • Generate a ConfigurationHelper that reads from appsettings.json
  • Ask AI to write 5 login tests using the generated page objects
Reading what was generated
  • Walk through every generated file — what is each class doing?
  • Identify: namespaces, class declarations, constructor injection
  • Spot locators — GetByRole, GetByLabel, GetByText
  • Run the tests from Test Explorer and watch them pass
  • Use the debugger to step through a test line by line
  • Write a short notes doc: "what I understand / what I don't yet"
The teaser approach: You're not expected to understand every line yet — that's Month 3. The goal is to have a real, running framework in front of you. Seeing the finished picture first makes the C# you learn later feel purposeful, not abstract.

Week 7 — Playwright fundamentals

Setup & core API
  • dotnet new nunit · dotnet add package Microsoft.Playwright
  • playwright install — download Chromium, Firefox, WebKit
  • IBrowser, IPage, IBrowserContext lifecycle
  • page.GotoAsync(), page.TitleAsync(), page.ScreenshotAsync()
  • Headless vs headed mode, slow-motion option
Locators & assertions
  • GetByRole(), GetByText(), GetByLabel(), GetByPlaceholder()
  • GetByTestId(), Locator() with CSS and XPath
  • ClickAsync(), FillAsync(), PressAsync()
  • Expect(locator).ToBeVisibleAsync(), ToHaveTextAsync()
  • ToHaveURLAsync(), ToBeEnabledAsync()
  • Automate full login → search → logout flow

Week 8 — Playwright advanced & framework v1

Advanced Playwright
  • WaitForSelectorAsync / WaitForLoadStateAsync / WaitForURLAsync
  • FrameLocator for iframes and embedded content
  • New tab and popup handling via page events
  • dialog.AcceptAsync() / DismissAsync() for browser alerts
  • SelectOptionAsync for dropdowns
  • Table row iteration using locator.AllAsync()
Framework v1 structure
  • Pages/ — LoginPage, HomePage, CheckoutPage classes
  • Tests/ — test classes organised by feature
  • Config/ — appsettings.json + ConfigurationHelper
  • BasePage and BaseTest with setup/teardown hooks
  • Screenshot on failure, HTML report with ExtentReports
  • 20 end-to-end tests against an e-commerce site

Week 12 — Fix the framework manually + AI

Manual refactoring (you lead)
  • Open the AI-generated framework from Month 2, Week 6
  • Rewrite any page object you don't fully understand from scratch
  • Replace hard-coded values with config-driven properties
  • Add proper exception handling around browser interactions
  • Write data-driven tests reading test data from JSON files
  • Add NLog or Serilog for structured logging to a file
AI as pair programmer (not author)
  • Use Copilot to review your refactored code and suggest improvements
  • Ask AI to explain why a test is flaky — then fix it yourself
  • Prompt AI for parallel execution config, then implement and verify it
  • Add NUnit Retry attribute for flaky test resilience
  • Tag tests by category: smoke, regression, e2e
  • Hook the suite into GitHub Actions — all tests green on push
The payoff: In Month 2 you used AI to build something you couldn't fully read. Now you can read, rewrite, and improve every line. AI has shifted from author to assistant — which is exactly where it belongs in a professional QA workflow.
